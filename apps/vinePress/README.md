# vinePress（藤压）

面向个人媒体库的**文件整理与批量归档工具**：自动识别「专辑 / 小说 / 图册 / 漫画 / 乐谱 / 演唱会 / 视频 / 资料」等 9 类目录，导入为可编辑的归档项目，批量写入说明文件，并按**最小压缩单位**批量压缩导出（可设密码、注释、分卷），输出目录与原始目录的相对路径保持一致。

> 技术方案与 `VinePalmaCursor` 完全一致：**Tauri 2.x + Rust + TypeScript + Vite**（详见 [AGENTS.md](./AGENTS.md)）。

---

## 1. 背景与目标

现有资料库（音乐专辑、小说、画集图册、乐谱、游戏 CG 等）以多层文件夹形式分散存放，人工逐个打包效率低且格式不统一。vinePress 的目标：

1. **智能扫描**：递归扫描目录，自动把「叶子内容目录」判定为压缩单位（Unit），把「分类容器目录」继续下钻。
2. **可编辑项目**：识别结果导入为项目，可增删条目、修改元数据（标题、艺人、发行日期、分类、备注……），项目可保存/恢复。
3. **说明文件批量生成**：为每个单位生成 `<单位名>.txt` 说明文件（专辑信息 / 资料信息 / 作品信息三种模板），内容由元数据 + 扫描统计（文件数、格式、分辨率、曲目）自动合成。
4. **批量压缩导出**：以单位为最小压缩单位打包，输出路径镜像原始相对路径，支持密码（写入文件名 `［密码］` 标签）、压缩注释、900 MiB 分卷。

## 2. 智能识别规则

自上而下递归判定每个目录（扫描根目录强制视为容器）：

```
classify(D):
  1. 若 D 含「内容文件」                 -> 单位（叶子），停止下钻
  2. 若 D 无子目录
       且 含非系统文件（含 .txt）         -> 单位
     若 D 无子目录且仅系统文件/为空       -> 忽略
  3. 若 D 名是「类别词容器」（画集/小说/CG…）-> 容器：继续下钻
  4. 若 D 的子目录名全部为「碟片/分卷名」 -> 母文件夹单位（多碟合一打包）
  5. 否则                               -> 容器：继续下钻每个子目录
```

此规则之上还有一层**手动覆盖**（`overrides`，持久化在项目文件里，扫描时优先判定）：

```
classify_with(D, ov):
  1. 若 D ∈ ov.force_units      -> 单位（停止下钻，子目录整体并入 = 合并/拆分）
  2. 若 D 是任一覆盖路径的祖先   -> 容器（保证深层覆盖可达）
  3. 若 D ∈ ov.force_containers -> 容器
  4. 否则走 classify(D)         （ov 为空时行为与历史版本完全一致）
```

关键判定细节：

- **内容文件**：图片（jpg/png/gif/webp/bmp/tiff…）、音频（flac/mp3/wav/ape/m4a…）、视频（mkv/mp4/avi…）、电子书与文档（pdf/epub/azw3/doc/cbz…）、压缩包（rar/7z/zip）、字幕歌词（lrc/srt/ass）、光盘镜像等；
  **排除**：`.txt`（说明文件，如 `KSLA.txt`、`01_Key Sounds Label.txt`）、`desktop.ini`、`.log`、`.bat`、`.bak`、`.cfg`、`.ini`、`Thumbs.db`、空目录。
- **碟片/分卷名（part-like）**：`Type-A/B/C/D`、`通常盤`、`…盤`、`BK`、`Scan(s)`、`booklet`、`第NN巻`、`第N章`、`Volume NN`、`Vol.NN`、`HT01..HT04`、`Disc N` / `DISC N` / `CD N`、`Side A/B`、`FLAC`、`画像集`、`ジャケット`、`内页`、`封皮`、`Card/Detail/Icon/[Overview]`、`Music Video DVD`、`CS Edition`、`backgrounds/dialog assets/events/gacha banners/story/units`、`官方乐谱/钢琴谱/其他乐器`、`[Disk N]` 结尾、**含 6~8 位纯数字方括号码**（`[220930]`、`[220602]`）等。
- **类别词容器**：`画集`、`漫画`、`小说`、`CG`、`壁纸`、`同人誌`、`日历`、`乐谱`、`卡片收藏`、`游戏`、`电子书`、`回收站`、`_回收待删` 等 → 一律视为容器继续下钻。
- **无内容的中间目录**：既不含内容文件、又不是类别词容器，且子目录也非分卷名时 → 容器下钻（例：`003 2000 AIR\CG` → 下钻到单位 `AIR CG`）。
- 特例：`_回收待删` 这类仅含 `.txt` 的叶子仍判为单位（与基准输出一致）。

## 3. 功能特性

### 3.1 扫描与导入
- 选择根目录 → 递归扫描 → 输出「容器树 + 单位列表」（单位数、体积、文件数）。
- 扫描根目录自身的直属散件**不入单位**（识别模型边界），完成后 toast 提示「根目录有 N 个散件未纳入单位」（`root_loose`）并写入进度日志。
- 识别类型自动标注：`专辑 / 小说 / 图册 / 其它`（依据所在路径的类别词与内容构成）。
- **扫描结果可手动修正**（写入 `overrides`，随项目保存、重扫后仍生效，节点上显示锁定徽标）：

  | 按钮 | 语义 |
  | --- | --- |
  | 强制为单位 | 把当前容器**本身**变成压缩单位，不再下钻（＝「拆分」） |
  | 强制为容器 | 即使按规则会判为单位也继续下钻 |
  | 并入上级 | 把所选单位的**父目录**整体设为单位；**会吸收同级兄弟单位**，确认框列出将被一并吸收的名单（仅单位节点可用） |
  | 恢复自动识别 | 把该路径从 `overrides` 移除，回到自动规则 |
  | 重命名目录… | 直接改磁盘目录名，并同步该条目**及所有子孙条目**的 `rel_path`/`name`，目录内 `<旧名>.txt` 一并改名为 `<新名>.txt`，保证 压缩包名 ≡ 目录名 ≡ 说明文件名 |

- **`overrides` 为空时行为与历史版本完全一致**（514 单位 ground truth 基准锁死，2026-10-08 重定）。

### 3.2 项目管理
- 项目以 `vinepress.json` 持久化（项目名、根路径、输出路径、密码方案、条目元数据）。
- 批量编辑：统一艺人 / 分类 / 年份 / 标签；支持搜索、按类型过滤、按路径排序。

### 3.3 自动识别填充（Auto-Fill）

从**文件夹内的实际文件**推断条目元数据，避免逐条手填。用户可选择**填充哪些字段**、以及**填充范围**（当前条目 / 已选条目 / 全部条目）：

| 字段 | 数据来源（优先级从高到低） |
| --- | --- |
| 标题 | 已有说明文件 `【专辑名称/作品名称】` → 音频标签 ALBUM/TIT2 → 目录名清洗（去序号、方括号标签、`／艺人` 后缀） |
| 艺人 | 已有说明文件 `【艺人】` → 音频标签 ARTIST → 目录名 `／` 之后的部分 |
| 发行日期 | 已有说明文件 `【发行日期】` → 音频标签 DATE → 目录名 `[2001.08.10]` → 年份 `(2001)` |
| 唱片公司 | 已有说明文件 `【唱片公司】` → 音频标签 LABEL/ORGANIZATION → 目录号前缀（推测） |
| 规格品番 | 已有说明文件 `【规格品番】` → 音频标签 CATALOGNUMBER → 目录名 `[KSLA-0098]` 段 |
| 出版方 | 已有说明文件 `【出版方／发行商】`（忽略"本地资料未记录"类占位值） |
| 评级 | 已有说明文件 `【最高位】` |
| 曲目列表 | 已有说明文件 `【曲目列表】` → `*.cue` TRACK TITLE → 音频文件名编号 |
| 标签 | 文件构成（`flac / cue / log / img / pdf / png …` 由实际扩展名推导） |
| 备注 | 目录内 `readme / 说明 / 简介 / 资料 / note*.txt` 正文、说明文件 `【备注】` |
| 所属作品 / 分类 | 目录层级（`NNN ` 序号目录 → 作品，直接上级 → 分类） |

音频标签解析支持 **FLAC Vorbis Comment**、**ID3v2.3/2.4**（TIT2/TPE1/TALB/TDRC/TXXX）、**WAV LIST-INFO**，只读文件头，不整文件加载。

交互：点「自动识别填充」→ 勾选字段与范围 → 后端返回**逐条提案**（新值 + 来源 + 原值）→ 预览表格逐行/逐字段勾选 → 应用。**不直接改写**，任何一条都可以拒绝。

### 3.4 文件浏览与文件级操作

选中条目后，底部**文件面板**显示该单位目录（或任意目录）的实际内容：

- **浏览**：目录/文件列表（大小、类型、修改时间）、上级导航、双击进入子目录、「全部文件」开关（默认隐藏系统/隐藏文件）；
- **打开**：用系统默认程序打开文件/文件夹；**定位**：在资源管理器中选中该文件；
- **新建分类（文件夹）**：在根目录或任意位置创建新目录；
- **重命名…**：改磁盘目录/文件名（同名视为无变化；拒绝非法字符、保留名 `CON`/`NUL`…、尾随点与空格）；
- **删除**：移入**系统回收站**（可找回，绝不永久删除），快捷键 `Delete`，确认框列出待删名称，完成后自动刷新文件面板并重扫；
- **复制 / 移动到…**：把选中的文件或整个条目目录复制/移动到指定目录（跨盘自动退化为复制+删除）；
- 所有写操作都被**限制在项目根目录内**（路径前缀校验），并拒绝目标位于源内部（避免复制进自身子目录）。

### 3.5 分类与重组（手动整理工作流）

「创建分类并添加」= 新建一个分类文件夹 + 把选中条目的**副本**放进去，等价于在文件结构里"复制一份重新手动整理"：

1. 在文件面板或条目表选中若干条目；
2. 新建分类名（如 `待整理 / 精选 / 2024 增补`）→ 自动创建 `<根>/<分类名>/`；
3. 条目目录被复制进去，**原目录不动**；
4. 重新扫描 → 新分类与其中的条目出现在目录树与表格中（识别为新的条目，可单独设定密码方案/导出）。

同理可用「移动到…」做真正的搬迁（如把散落的子目录并入某个作品目录）。

**拆分复合文件夹（一目录一说明）**：自动识别会把「直属含内容文件」（哪怕只有一张封面图）或「全为分卷名」的目录**整体作为一个单位**，列表里只显示总文件夹。若希望里面每个专辑/子目录各自成条目、说明文件一专辑一文件，在条目**详情面板「含 N 个子目录」区块点「拆分为子目录…」**（或目录树选中该节点 →「强制为容器（拆分）」）→ 自动重扫后子目录各自成为条目。拆分前若总目录**直属有散件内容文件**会先弹警示：这些散件拆分后不属于任何子单位、不会被打包导出，建议先在文件面板移入子目录。选中节点点「恢复自动识别」可撤销拆分。表格名称列的「N 子目录」角标可快速识别这类复合单位。

### 3.6 类型可扩展

当前内置 **9 种类型**：`album` 专辑、`novel` 小说、`artbook` 图册、`comic` 漫画、`score` 乐谱、`concert` 演唱会、`video` 视频、`document` 资料、`other` 其它；用于**说明文件模板**、展示徽标（各自配色）、类型筛选与批量编辑。CG、壁纸、卡片收藏、设定集、同人誌、游戏 CG 等视觉合集归入「图册」。

- 类型判定为**两层结构**，集中在 `scan/rules.rs::kind_verdict`（返回 类型 + 置信度 + 是否需复核），`infer_kind` 只是取类型的薄包装：
  - **路径门（Layer1）**：「最近段」类别意图优先——分类文件夹（段名恰为类别词，如 `画集/`、`漫画/`、`小说/`、`乐谱/`、`资料/`）直接生效；类别词仅嵌在标题里（如 `XX画集特典CD`）则以内容裁决——**含音频一律专辑**；音乐/公演语境（音乐/专辑/公演/ライブ…）+ 纯视频 → 演唱会，发行物带 bonus MV（音频+视频共存）仍是专辑；`guide` 弱英文词在有图时让位向上（扫描画册不判资料）；远距根词（`Key小说图册`）不抢图像/视频内容。门命中 → 置信度 1.0、不复核。
  - **内容评分（Layer2，仅路径无类别词时）**：面向**堆叠/未分类散件**，按证据打分取最高——字节主体（音频/图像/视频/文档/文本占比）、cue/日志、分轨与页码编号、剧集编号、章节卷数、体裁词（epub/正文行数/漫画归档 cbz/cbr）、音乐与公演语境词、封面匹配度等加权求和；**置信度 = 最高分与次高分的差距**，差距小于 0.7 或结果为「其它」→ 标记**待人工复核**。
  - **内嵌封面交叉比对**（`src-tauri/src/kindx.rs`）：音频+图像混合且置信度不足时，取单位根目录 FLAC/MP3 的内嵌封面与单位内图片做感知指纹（dHash，汉明距离 ≤10，最多 16 张）比对——匹配度高 → 改判专辑，匹配度低 → 图册/漫画；高置信单位直接跳过、不读盘。
  - **复核标记** `needs_review` 贯通扫描结果 → 表格、目录树、详情三处「复核」徽标；全局搜索直接搜「复核」即可列出全部待复核条目；手动改类型（详情下拉或批量编辑）自动清除标记。**音视频混合内容**（音频与视频都有实体且量级相近——「作品目录里既有专辑又有动画」这类）即使路径门高置信也标复核，提示人工确认。
  - 判定回归基准：`cargo test --test ground_truth`（514 个单位的**边界**锁死，不锁类型；2026-10-08 数据漂移后重定）+ `cargo test --test kind_audit`（9 类分布核对 + 低置信清单）；改动判定逻辑必须两跑。
  - 已知边界：扫描只分类**子目录**，扫描根目录自身的散文件不入单位——`root_loose` 收集后以 toast「根目录有 N 个散件未纳入单位」+ 进度日志提示。
  - 前端类型全集唯一来源 = `src/state.ts` 的 `KINDS`（类型下拉、批量编辑、徽标、筛选同源）；新增类型只改 `KINDS` + 徽标 CSS + 判定与模板分支。
- 后续会把「类型」做成**类型包（type pack）**：字段表 + 判定规则 + 说明文件模板 + 自动填充字段来源，均为数据配置，无需改动扫描逻辑，从而支持更多自定义类型。

### 3.7 说明文件批量生成
三种模板（生成到单位目录内 `<单位名>.txt`，UTF-8）：

| 模板 | 适用 | 字段 |
| --- | --- | --- |
| 专辑信息 Album Info | 音乐专辑 | 专辑名称、艺人、发行日期、唱片公司、规格品番、文件格式、曲目数量、曲目列表 |
| 资料信息 Publication Info | 画集 / 图册 / 小说 | 作品名称、所属作品、分类、备注、资料类型、出版方、发行日期、文件格式、分辨率统计、文件数量、册数卷数、收录内容 |
| 作品信息 Single/多版本信息 | 多版本单曲 | 上述字段 + 各版本（Type-A 等）收录曲目、本资源收录 |

统计信息（分辨率、格式分布、子目录清单）由扫描器直接汇总。

生成前可在条目详情面板点「预览说明」查看**完整渲染结果**（不写盘，内容与最终写入一致）。

**字段级对比**（编辑菜单「对比说明文件（字段级）」）：把现有 `<单位名>.txt` 与按当前条目重新渲染的结果逐字段对比，按新渲染的模板顺序列出 新增 / 变更 / 移除 / 未变（默认隐藏「未变」，可勾选显示），多行字段（曲目列表）整块对比；现有文件不存在时提示「将全部新建」。解析与 diff 在 `meta::parse_note_blocks` / `meta::diff_note_text`（纯逻辑，有单测）。

**批量核对**（工具菜单「核对说明文件…」，只读不写盘）：对范围（有勾选 = 已选条目，否则全部）逐条渲染并与磁盘上的说明文件比对，进度实时回报、可取消；结果按单位列出状态徽标（**缺说明 / 缺字段 / 有变更 / 多余字段 / 一致 / 错误**）与缺失字段清单，顶部汇总计数。点任意行跳转该条目并打开字段级对比，可「← 返回核对清单」。核对为 JobState 互斥任务（与生成/导出不并发），核对确认存在的条目会同步 `has_notes`。纯逻辑 `meta::audit_note` + 命令 `start_note_audit`（事件 `note-audit-progress`），有单测。

### 3.8 批量压缩导出
- **最小压缩单位**：每个单位一个压缩包，内部结构 = 单位目录内容（不套多余的根目录层）。
- **路径镜像**：`<输出根>\<原相对路径>\<单位名>\<单位名> [密码].rar`；选 ZIP 时为 `…\<单位名>.zip` 且**不带密码标签**（压缩包始终位于镜像单位目录**内部**）。
- **格式**：
  - `rar`（默认）：调用本机 WinRAR `Rar.exe`（无 7-Zip 回退），支持密码与分卷；缺失时导出前自检直接报错。
  - `zip`：内置 `zip` crate（deflate）实现，**不依赖任何外部工具**；不支持加密与分卷（密码方案会被忽略），选中 ZIP 时分卷/加密控件自动禁用并给出提示。
- **密码**：密码方案对应密码本「用途 → 密码池」；RAR 密码同时用于文件名标签（`单位名 [密码].rar`）与头加密 `-hp`（连文件名一起加密）。
- **注释**：压缩包 comment = 说明文件正文，RAR 与 ZIP 均按 **GBK** 编码写入。
- **分卷**：仅 RAR，900 MiB（943718400 字节）阈值 → `name.part1.rar`。
- **说明文件**：导出前按设置生成 `<单位名>.txt`（UTF-8 BOM + CRLF）写入单位目录并同步打包，渲染结果同时用作注释（每单位只渲染一次）。
- **导出前自检**：开始前检查 RAR 缺失、单位目录不存在、注释与说明文件不同步、ZIP 不支持分卷/加密、密码方案引用失效、输出根不可写、已存在且不覆盖（将跳过）——分级列出 →「取消 / 仍然导出」。
- **可取消、可续跑**：进度实时回报（单位进度 + 字节进度 + 失败清单），随时可取消；已存在且不覆盖 → 跳过（状态标「已存在」）；覆盖模式先把旧包改名 `*.prevbak`，成功才删、失败自动还原。

### 3.10 查找重复文件

工具菜单「查找重复文件…」（只读，JobState 互斥、可取消）：

- **两级判定**：递归收集普通文件（跳过重连点 symlink/junction、`desktop.ini` / `Thumbs.db`、空文件）→ 按**大小**分组（仅 size 出现 ≥2 的为候选）→ 候选逐个做**全文 SHA-256**（128 KiB 流式，`sha2`）→ 大小 + 哈希一致才成组；同大小不同内容不会误报。
- **进度**：扫描阶段每 200 文件回报一次（进度条脉冲），哈希阶段逐个回报 `i / total`；随时取消，取消时返回已得结果。
- **结果**：按大小降序列出每组（大小 × 份数 + 哈希前缀），组内按字典序、**首个默认保留**，其余副本默认勾选；「定位」把文件面板切到该文件所在目录并选中。
- **删除**：确认框列出文件名 → `trash_items` **移入系统回收站**（绝不永久删除）→ 从结果中移除（不足 2 份的组自动消失）。纯逻辑 `dupes::find_duplicates`（回调注入进度、AtomicBool 取消），命令 `start_find_duplicates`（事件 `dupes-progress`），有单测（含同大小异内容不误报、系统文件跳过、进度 total）。

### 3.12 导出清单与完整性校验

每次导出结束后，把本次触及的压缩包记入 `<输出根>\vinepress-manifest.json`（`manifest.rs`，纯逻辑）：

- **清单**：逐文件记录 `rel_path`（相对条目）、`archive`（相对输出根、正斜杠）、`size`、`mtime_ms`、`sha256`、`written_at`；按 `archive` 键 upsert 覆盖不追加；size + mtime 未变的条目跳过重哈希；临时文件 + rename 原子落盘。**中途取消的导出不写清单**（校验时该包会列入「未入清单」）。
- **进度**：`run_export` 在逐单位循环之后、`finished` 事件之前发 `phase = "manifest"` 事件——每文件一次「计算校验和 i/N」，收尾一条「导出清单已更新（本次变动 X · 累计 Y 个文件）」或保存失败的 error 事件。
- **校验**：工具菜单「校验导出完整性…」（只读，JobState 互斥、可取消，事件 `verify-progress`）逐文件核对**存在性 → 大小 → SHA-256**（128 KiB 流式），并扫描输出根收集**未入清单**的 rar/zip；结果为摘要计数 + 异常表（缺失 / 大小不符 / 哈希不符 / 读取失败，逐行期望/实际大小）+ 未入清单列表；取消时返回已检部分并标注「已取消」。
- **测试**：`manifest_test.rs` 5 测试（SHA-256 标准向量、save/load/upsert、unchanged 判定、四类异常 + 未入清单 + 进度回调、无清单报错与取消短路）；zip e2e 追加断言（导出后清单 2 条且校验全过 → 跳过重导仍一致 → 篡改磁盘后报告 1 个不一致）。

### 3.14 按清单增量导出

压缩参数提供「增量跳过未变动单位（按导出清单）」（`ArchiveSettings.incremental`，右侧面板 / 导出设置 / 设置默认值三处同步，默认关）：

- **指纹**：`export::unit_fingerprint` = 源目录 walk（文件数 / 总字节 / 最新 mtime，跳过重连点）+ 影响包内容的设置（格式、分卷、加密、注释、说明开关）+ 密码 + 说明正文哈希（`write_notes || comment` 时纳入；受管说明文件 `<单位名>.txt` 不计入 walk，由正文哈希覆盖）。SHA-256 单行入清单 `ManifestFile.fingerprint`。
- **跳过判定**（导出开始时的清单快照）：指纹非空且一致 **且** 磁盘压缩包 size+mtime 与清单一致 → 发 `status = "skipped"`、`message = "增量跳过（未变动）"` 事件，**不重写说明文件、不重打包**，指纹保留。
- **指纹维护**：仅创建成功时写入（按**写盘后**最终状态重算，覆盖说明写入/旧说明清理）；非增量导出重建写**空串作废**（防止源回滚等场景误跳过）；「不覆盖跳过」保留旧指纹。旧清单缺该字段 → 空 → 安全降级为全量导出。
- **说明**：导出流程改为先渲染正文（单次渲染不变）→ 增量判定 → 需要时才 `write_note_file` 落盘；顺带修复资料信息模板（`render_publication`）**不渲染备注**的缺口——图册/小说编辑备注后现在会进入说明文件与压缩注释。
- **自检**：`preflight_export` 在 `incremental = true` 时追加 info 级提示（无清单 → 「本次将全量导出」；有清单 → 「未变动单位将按清单跳过」），自检弹窗以 `.pf-info` 样式渲染。
- **测试**：`unit_fingerprint_stability`（稳定性、正文开关、设置/密码敏感、说明文件排除）、`incremental_zip_export`（首跑全建记指纹 → 未变动全跳过且 zip/mtime 不变 → 加文件仅该单位重建 → 备注变仅该单位重建 → 非增量重建作废指纹 → 再开增量不可跳过直至重记 → 最终校验一致）；`check10.cjs` 11 断言（三处表单往返、info 自检渲染、跳过日志带原因、完成计数）。

### 3.15 交互与体验优化（脏状态 / 多选 / 列宽 / 响应式）

纯前端整体 UX 打磨一轮（`check11.cjs` 25 断言，无 Rust 改动）：

### 3.16 命名检查与修复（网盘适配）

工具菜单「命名检查与修复…」——上传网盘前的全盘文件名合规检查与批量修复（规则调研自百度网盘 / 阿里云盘 / 天翼云盘 / 115 / 夸克 / 腾讯云 COS）：

- **档案（Profile）**：`Windows 本地/同步盘`、`百度网盘`、`阿里云盘`、`天翼云盘`、`通用网盘`、`对象存储/COS（严格）` 六档共用核心规则——非法字符 `\/:*?"<>|`、Windows 保留名 `CON/PRN/AUX/NUL/COM1-9/LPT1-9`（含扩展名形态）、首尾空格与尾点、单段 255 UTF-16 字符、相对路径 >260 警告；strict 档追加 `` ` ^ { } [ ] ~ % # `` 等对象存储不推荐字符提示。档案经 `name_profiles` 下拉选择，选择随修复执行生效。
- **检查**（`check_names(root, profile)`，只读、不写盘）：一次全盘目录树扫描，逐项给出 **级别**（error / warn）、**类型**（目录 / 文件 / 根目录）、**原因**、**建议新名** 与是否可自动修复；根目录项只提示不可修（rel 模型边界）；同级建议名自动去重（大小写不敏感 + ` (2)` 序号）。结果按 严重度 + 路径 排序，顶部汇总（扫描数 / 问题数 / 可修复数），支持全选/反选可修复项。
- **修复**（`fix_names(root, items)`，两步确认）：勾选可修复项（或「全选可修复」）→ 按钮 4 秒武装期内再次点击才执行 → 按 rel 段数**浅层优先**批量磁盘改名，父目录改名后自动位移后续待改项的 rel；条目 `rel_path`/`name`、`overrides`、选中态与文件面板当前目录同步（`applyRelShift`），目录内 `<旧名>.txt` → `<新名>.txt` 一并改名；完成后自动重扫 + 复检，toast 报告「已修复 N / 失败 M」。
- **建议名**（`naming::sanitize`）：非法字符转全角（`:`→`：`、`*`→`＊`、`?`→`？`、`"`→`＂`、`<`→`＜`、`>`→`＞`、`|`→`｜`）、去控制符与零宽字符、trim + 去尾点、保留名在首点前插 `_`（`NUL.txt` → `NUL_.txt`）、空名兜底「未命名」、超长按 UTF-16 255 截断并保扩展名。
- **实现**：纯逻辑 `naming.rs`（`Profile` / `check_name` / `sanitize` / `check_tree` / `dedupe` + 9 单测），命令 `name_profiles` / `check_names` / `fix_names`；菜单项 `data-busy="block"`、修复入口 `busyGuard()`；`check14.cjs` 43 断言（菜单忙碌守卫、散件提示、档案切换、两级确认修复、重扫复检、表格改名同步、拆分警示）。

## 背景（两份审阅报告的结论）

**稳定性缺陷**：① `fsops::copy_dir` 目标可在源内部 → 复制进自身子目录会无限递归（fsops.rs:214）；② `open_path` 用 `cmd /c start` → 文件名含 `&` 等元字符有命令注入风险（fsops.rs:103）；③ `Project::save` 非原子写，崩溃即损坏且无 `.bak`（project.rs:203）；④ 导出 `overwrite=true` 时**先删旧压缩包再创建**，失败即丢旧包（archive.rs:113）；⑤ worker 线程 panic → `end_job` 不执行 → 之后所有任务永久报「已有任务正在运行」（commands.rs:102/215）；⑥ 说明文件/导出拼 `rel_path` 不校验 `..`；⑦ 模态框 Esc 监听 `{once}` 失效、遮罩不可点关、异步确定可重复提交；⑧ `mergeEntries` 回滚手工改的 `name`，且「目录名」手工改只改导出名不改磁盘 → 压缩包名 ≠ 目录名（README §3.1 承诺的合并/拆分/改名同步全部缺失）。

**性能缺陷**：全部 14 个 command 都是 sync → `scan_directory`/`auto_fill_proposals`/`copy_items`/`move_items` 等**阻塞 UI 主线程**；`UnitStats.sample_names`（每单位至多 4000 名 ×2 处）在扫描/IPC/存档中传输但**无任何消费者**；`meta::extract` 对同一子树最多 4 次独立递归遍历、`find_readme` 无条件执行；导出每单位 `render_note` 两次（export.rs:121+132）；`probe_wav` 整文件读入内存只为 44 字节头（notes.rs:168）；`merge_scan` O(n²)。

**功能缺口（README 承诺）**：合并（单位并入上级）、拆分（容器强制为单位）、目录改名同步、ZIP 格式是空壳控件、说明文件预览、导出前自检、文件面板删除/重命名。

用户已确认：四个方向（稳定性+性能 / 手动修正 / 交互打磨 / 新功能）全做，允许引入轻量常用依赖。

## 新依赖（均为成熟小依赖，已核实）

- `zip`（crates.io 现行 8.x，MSRV 1.88 ≤ 本机 1.98，deflate 内置）：内置 ZIP 导出；`ZipWriter::set_raw_comment(Box<[u8]>)` 可写 GBK 原始注释字节（实现时用 WinRAR 验证显示，异常则改 UTF-8 并记录）

### 风险与决策点（已定）

- **overrides 使部分覆盖路径在「祖先有内容文件」时优先下钻**——保证深层覆盖生效，空 overrides 完全向后兼容（基准锁死）。
- **ZIP 不做加密/分卷**（避免 AES/传统加密复杂度），preflight 明示；RAR 仍是主力格式。
- **并入上级会吸收同级单位**——结构所限，用确认框明示将被吸收的兄弟列表，不搞静默合并。
- **name 字段改只读**——用户唯一改名途径是磁盘重命名，保证 压缩包名 ≡ 目录名 ≡ 说明文件名。
- 磁盘剩余空间检查、撤销栈、查重哈希等留 §8 构思不在本轮。
