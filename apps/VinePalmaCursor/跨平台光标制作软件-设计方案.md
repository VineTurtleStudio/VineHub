# VinePalmaCursor —— 跨平台鼠标指针制作软件 设计方案

> 项目名：**VinePalmaCursor**（沿用 VinePalma 品牌前缀，命名协商于 2026-09-10）
>
> 目标：制作一款跨平台（Windows / Linux / macOS）的光标制作软件，实现甚至超越现有工具（Axialis CursorWorkshop、RealWorld Cursor Editor、Pixie Cursors、Cursors-4U 在线编辑器）的基础功能。
>
> 技术栈：**Tauri 2.x + Rust + TypeScript + Canvas 2D**（已确认）

---

## 1. 项目概述

面向普通用户与像素艺术家，提供"画 → 预览 → 打包 → 安装"一站式流程：

- 像素级画布编辑（工具、图层、撤销）
- 动画时间轴（帧、洋葱皮、帧延迟）
- 热点（Hotspot）精确标定
- 多尺寸/多平台导出与整套主题打包
- 一键安装（Windows）/ 复制安装（Linux）/ 引导导入（macOS）

与现有工具的差异化亮点（可选，见 §8）：
- SVG 矢量 → 光标
- 模拟桌面实时预览（多尺寸、深浅背景、动画速度）
- 颜色 Token 一键换色
- 批量转换整套主题

## 2. 目标格式（跨平台矩阵）

| 平台 | 格式 | 说明 |
|---|---|---|
| Windows | `.cur`（静态）/ `.ani`（动态） | 事实标准，资料最全，字节级规范见 §7 |
| Linux X11/Wayland | XCursor（目录 + `index.theme`） | 每尺寸一张 PNG，放入 `~/.icons/<主题>/cursors/`，依赖 XCURSOR_THEME |
| macOS | `.cape`（Mousecape） | 无官方生态，社区标准，参考 Mousecape 开源源码 |
| 通用导出 | PNG 序列、GIF | 作为中间素材与预览用 |

**跨平台真机预览限制**（重要）：
- Windows：可调用 `SystemParametersInfo(SPI_SETCURSORS)` 真正设为系统光标 → 应用内"试用"可行
- Linux：可临时写 `~/.icons` 并设置会话环境变量（部分桌面有效）
- macOS：**无 API** 可临时切换系统光标，只能引导用户装 Mousecape 导入 `.cape`

→ 因此产品内嵌"**模拟桌面预览**"是跨平台统一且必须的方案；Windows 真机试用作为加分项。

## 3. 技术选型与理由

| 维度 | 选择 | 理由 |
|---|---|---|
| 桌面壳 | Tauri 2.x | 体积小（~10MB）、内存低、Rust 安全高性能、三平台分发 |
| 后端 | Rust | 字节级格式编解码精确可控；批量转换并行快；`cargo test` 测格式 |
| 前端 | TypeScript + Vite | 类型安全、构建快、生态成熟 |
| 渲染 | Canvas 2D（offscreen canvas） | 像素网格/放大/预览灵活，无需重型库 |
| UI 框架 | （可选）React / Solid / 原生 TS | 初期裸 TS + 轻量组件即可，避免过度设计 |
| 核心编解码 | **Rust 库层** | 独立于 UI，可单测，复用进 CLI（§4 架构决策） |

前置环境：Node.js LTS、Rust (rustup stable)、git、Tauri CLI。Windows 还需 WebView2（Win10/11 自带）。

## 4. 架构设计

### 4.1 核心原则：编解码库层与 UI 完全解耦

格式读写是**确定性纯逻辑**，与 UI 无关。独立成库带来：可单测、可复用（CLI/批量工具）、未来可移植 WASM。

```
mouse-pointer-studio/
├── src-tauri/                    # Rust 后端
│   ├── Cargo.toml
│   ├── tauri.conf.json           # 窗口、权限、打包配置
│   ├── capabilities/default.json # Tauri 权限（fs/dialog 等）
│   ├── src/
│   │   ├── main.rs               # Tauri 启动
│   │   ├── commands.rs           # #[tauri::command] 桥接前端
│   │   └── codec/                # ★ 纯逻辑库层（零 Tauri 依赖）
│   │       ├── mod.rs
│   │       ├── bitmap.rs         # 内部 RGBA 图像+尺寸+热点结构体
│   │       ├── cur.rs            # .cur 读写（ICO 容器）
│   │       ├── ani.rs            # .ani 读写（RIFF/ACON）
│   │       ├── dib.rs            # RGBA ↔ DIB（XOR/AND mask）
│   │       ├── xcursor.rs        # Linux XCursor 主题生成
│   │       ├── theme.rs          # 15 角色映射 + 安装脚本生成
│   │       └── scale.rs          # 多尺寸下采样（最近邻/双线性）
│   └── tests/                    # codec 字节级单元/集成测试
├── src/                          # TypeScript 前端
│   ├── main.ts                   # 入口
│   ├── state/                    # 文档模型（帧/图层/热点/撤销栈）
│   ├── editor/
│   │   ├── canvas.ts             # 像素网格渲染（offscreen，缩放4x+）
│   │   ├── tools.ts              # 画笔/橡皮/填充/直线/取色/热点
│   │   ├── layers.ts             # 图层合并/可见/透明
│   │   └── timeline.ts           # 帧管理、洋葱皮、jiffies 延迟
│   ├── preview/                  # 模拟桌面预览（背景/尺寸/动画）
│   ├── api.ts                    # Tauri invoke 封装（类型化）
│   └── ui/                       # 面板：工具栏/图层/时间轴/导出向导
├── package.json / vite.config.ts
└── ...
```

### 4.2 数据流

```
前端文档模型 (frames × layers × hotspot)
        │  invoke("export_cur", {images, sizes, hotspots})
        ▼
Rust codec  ──► .cur / .ani / .xcursor / .cape / PNG / GIF
        │  invoke("import_file", ...)
        ▼
前端载入 RGBA 帧序列
```

前端永远只持有 RGBA 像素 + 元数据；所有"写文件"都走后端 codec，保证格式正确性集中在可测试处。

### 4.3 后端命令设计（MVP 集）

| command | 说明 |
|---|---|
| `export_cur` | 多帧(静态=单帧)/多尺寸 → .cur |
| `export_ani` | 帧序列+速率 → .ani |
| `import_image` | PNG/GIF/图片 → RGBA 帧（GIF 拆帧） |
| `import_cursor` | .cur/.ani 解析 → RGBA 帧+热点（回读编辑） |
| `export_xcursor_theme` | 全套 → index.theme + PNG 目录 |
| `export_cape` | （参考 Mousecape 源码） |
| `pack_theme` | 15 角色一套 + 安装脚本 (.inf / .ps1 / shell) |
| `preview_install_windows` | SystemParametersInfo 临时启用（Win 加分项） |

## 7. 格式规范速查（实现要点）

### 7.1 .cur（静态）= ICO 容器

```
ICONDIR（6 字节）:
  reserved  u16 = 0
  type      u16 = 2        // 1=ICO, 2=CUR
  count     u16 = 图像数/尺寸数

ICONDIRENTRY（16 字节 × count）:
  width      u8            // CUR 中常为 0（部分读取器忽略）
  height     u8            // 同上
  colors     u8 = 0
  reserved   u8 = 0
  planes     u16 = 热点 X  ★CUR 里被复用为热点横坐标
  bitcount   u16 = 热点 Y  ★CUR 里被复用为热点纵坐标
  size       u32 = 图像数据字节数
  offset     u32 = 图像数据相对文件偏移

图像数据（每个 entry）:
  BITMAPINFOHEADER（40B，带 biSizeImage）
  XOR bitmap（BGRA；32bit 带 Alpha 时 AND mask 仍保留，可全 0）
  AND mask（1bit/像素，行对齐到 4 字节）
```

要点：热点坐标是以**图像左上角为原点**的像素位置；同一 .cur 可含多尺寸，系统按当前 DPI 挑最合适的。

### 7.2 .ani（动态）= RIFF/ACON

```
RIFF('ACON')
├─ anih  chunk（核心头，cbSize=36）
│    nFrames  nSteps  iWidth  iHeight  nBitCount(32)  nPlanes
│    iDispRate（jiffies，1/60 秒）  bAttributes
├─ rate  chunk：每帧延迟的 u32 数组（可选）
├─ seq   chunk：帧播放顺序 u16 数组（可选）
└─ LIST('fram')  ×nFrames
     └─ icon chunk：内嵌一个单图 ICONDIR（type=2）
```

要点：`iDispRate` + `rate` 都以 1/60s（jiffies）为单位；每帧可独立热点，但整套保持一致避免抖动。

### 7.3 Linux XCursor

```
<主题>/index.theme
  [Icon Theme]
  Name=MyTheme
  Inherits=...
  Directory=cursors
  各 cursor 尺寸目录声明
<主题>/cursors/<name>_<size>.png   // 如 left_ptr_32.png
```
安装：复制到 `~/.icons/<主题>/`，重启桌面或 `xsetroot`/会话更新后生效；KDE 界面可直接选主题。文件名需符合 X11 光标命名（left_ptr, hand, text, wait…）。

### 7.4 macOS `.cape`（Mousecape）

无官方格式文档。**正确做法是直接读开源 Mousecape 项目的 Swift 源码**（`alexzielonka/Mousecape`）按其序列化方式实现；输出包配合 Mousecape 应用导入。

## 8. 差异化亮点（相对现有工具）

| 功能 | 现有工具 | 本产品 |
|---|---|---|
| SVG 矢量转光标 | Axialis 支持、多数不支持 | 规划支持 |
| 模拟桌面多尺寸预览 | RealWorld 有静态预览 | 增强：动画速度/深浅背景/真机安装预览 |
| 批量整套生成 | Axialis 批量、AI 工具 | 目录驱动一键 15 角色 |
| 三平台导出 | 各自为战 | 一键多格式 |
| 颜色 Token 换色 | Cutesor 有 | 可规划 |

好意过头即坏：MVP 优先把 **M1 链路做扎实**，亮点放 M4/M5。
